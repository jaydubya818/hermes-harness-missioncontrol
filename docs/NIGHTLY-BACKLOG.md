# Nightly backlog

Standing list for the scheduled nightly maintenance run. Items land here when
they are worth doing but out of scope for the night that found them, or when
they were investigated and deliberately ruled out. Check this file before
proposing work so the same ground is not re-covered every night.

## Open

- [ ] 2026-08-21 — Gate the worker's `success` claim against the evidence it attached — the orchestrator takes `execution.success` at face value (`if (!execution.success) await failRun(...)`), and `evaluateStepPolicy()` checks *that* artifacts exist, never what they say. The test-report artifact already carries `metadata.exit_code`, so `success === (exit_code === 0)` is a free cross-check for the test kind. Not done tonight because doing it properly means deciding, per step kind, what evidence the gate is entitled to demand — that is a contract change, not a patch. See `docs/HARNESS-INVARIANTS.md` invariants 2 and 4.
- [ ] 2026-08-21 — Stop the worker spreading its whole `WorkspaceContext` into the execute-step reply — `c.json({ ..., ...workspace!, ...result, step_events })` sends the echoed `envelope` and absolute host paths (`workdir`, `repoWorkspace`, `worktreePath`) back across the service boundary, and the orchestrator's `WorkerExecution` type declares only some of them. Narrow the reply to the fields the orchestrator actually consumes. Left alone tonight because it is a response-shape change with console and test callers to check, not a one-line fix. See `docs/HARNESS-INVARIANTS.md` invariant 3.
- [ ] 2026-08-21 — Declare a Node `engines` range — nothing enforces the `.nvmrc: 22` pin; `.nvmrc` is advisory and only nvm-family tools read it, so a contributor on another major installs and builds with no signal. Deliberately not added tonight: pnpm's `engine-strict` would start failing installs on Node 24 machines, so this needs a decision on whether to warn or block first.
- [ ] 2026-08-21 — Backfill timestamps when hydrating legacy persisted runs — `hydrateState` validates run shape and calls `syncRunState`, but does not stamp a missing `run.updated_at` or step `started_at`/`completed_at`. Read models each paper over this with their own `?? ""` fallbacks, which is how the artifacts date-filter bug hid; normalizing once at hydration would remove the whole class.
- [ ] 2026-08-22 — Decide whether `retryCurrentStep` should still accept a cancelled step — the resurrection bug was closed at the orchestrator route, but `packages/workflow-engine`'s `retryCurrentStep()` still lists `"cancelled"` among its retryable prior states, unlike every other `markCurrentStep*` helper (all of which refuse `completed`/`failed`/`cancelled`). Nothing else calls it today, so the hole is closed in practice; tightening the engine too is a shared-package behaviour change and wants a deliberate call on whether the state machine is allowed to un-cancel at all.
- [ ] 2026-08-22 — Stop `loadContextBundle` returning absolute host paths — `packages/memory-runtime/src/contextLoader.ts` puts fully-resolved host paths into `files[].path`, `trace.included[].path` and `trace.excluded[].path`, and `memory-api` returns them verbatim to the console. Same class as the worker leaking `workdir`/`worktreePath` (open item above): vault-relative paths are what every consumer actually uses. Not done tonight because it changes a response shape the console and the memory-runtime tests both read.
- [ ] 2026-08-22 — The `"bus"` memory class is unreachable — `classify()` in `contextLoader.ts` falls through to `"bus"`, but the candidate list is only `profile.md`, `hot.md`, `standards.md`, `recipes.md`, and `memory-api` writes bus entries to `wiki/projects/<id>/bus.md` which is never a candidate. So the context bundle can never carry the cross-agent bus that `MemoryClass` reserves a class for. Either wire `bus.md` into the bundle (a budgeting/priority decision) or drop the dead class.
- [ ] 2026-08-22 — Assess the harness contracts against MCP spec 2026-07-28 — the new revision moves the core to stateless request/response, strengthens OAuth/OIDC authorization, and versions the Apps and Tasks extensions. This repo is a Hermes harness whose service boundary is defined by `packages/contracts`, so the authorization and task-lifecycle changes are conceptually relevant. Explicitly *not* nightly work: a spec migration is a design exercise, not a surgical patch. Scope it before touching anything.
